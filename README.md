# موقع «العرض التقديميّ» — تاريخ مملكتيّ — البجروت المرنة

الرابط الحيّ: **https://gabimansoure-coder.github.io/presentation-bagrut/**

موقع ثابت (بلا خادم، بلا قاعدة بيانات، بلا تسجيل دخول) يرافق الطالب من اختيار الموضوع حتى المردودية، ويوجّهه بحسب المئشار دون أن يكتب له شيئًا. ما يكتبه الطالب يُحفَظ في `localStorage` على جهازه فقط.

## البنية

```
docs/                 ← هذا ما يُنشَر فعليًّا على GitHub Pages (فرع main، مجلّد /docs)
  index.html
  assets/
    app.js            ← كلّ منطق الموقع (توجيه، عرض الصفحات، التخزين المحليّ)
    style.css         ← النظام البصريّ (مُستعار من موقع «الجريدة الشخصية»، 06 الموقع)
    data.json          ← نسخة منشورة من data.json (انظر أدناه)
data.json              ← نسخة العمل الأصلية التي زوّدني بها المعلّم عند بدء المهمّة (لا تُستعمَل مباشرةً بعد اليوم الأوّل)
tests/e2e.mjs          ← اختبارات القبول (Playwright) — تُشغَّل تلقائيًّا ضمن npm run deploy
tools/deploy.mjs       ← سكربت النشر بأمر واحد
```

**مصدر الحقيقة الحيّ هو `docs/assets/data.json`** — هو ما يقرؤه الموقع فعلًا عبر `fetch`. ملفّ `data.json` في الجذر هو النسخة التي بدأنا منها المشروع ولم تعد تُستعمَل تلقائيًّا؛ عدِّل `docs/assets/data.json` مباشرةً.

## كيف أعدّل أمرًا للبوت

1. افتح `docs/assets/data.json`.
2. ابحث عن الرقم داخل `prompts` (مثلًا `"7"`) وعدِّل الحقل `x` (نصّ الأمر) أو `t` (عنوانه).
3. إن أردت نقل الأمر إلى مجموعة أخرى في صفحة «الأوامر للبوت»، عدِّل `promptGroups` كذلك (كلّ أمر يجب أن يظهر في `ids` لمجموعة واحدة بالضبط).
4. شغّل `npm run deploy` من مجلّد هذا المشروع.

## كيف أعدّل بندًا في المئشار

1. افتح `docs/assets/data.json`، وابحث عن `rubric.individual` أو `rubric.collaborative`.
2. كلّ بند له `pts` (نقاط البند كاملًا) و`items` (مصفوفة تفريعات، كلّ تفريعة `[نقاطها, نصّها]`).
3. **تنبيه:** الموقع لا يتحقّق تلقائيًّا من أنّ مجموع التفريعات يساوي نقاط البند، لكنّ `npm test` يفعل — شغّله بعد أيّ تعديل.
4. شغّل `npm run deploy`.

## كيف أعدّل أيّ نصّ آخر (المهمّة، المعجم، «ما وراء الكواليس»، قائمة يوم العرض)

كلّه في `docs/assets/data.json` تحت `task` و`glossary` و`bts` و`dayChecklist`. عدِّل النصّ المطلوب ثمّ `npm run deploy`.

## النشر — بأمر واحد

```bash
npm run deploy
```

هذا يشغّل خادمًا محلّيًّا، يُجري اختبارات `tests/e2e.mjs` (48 اختبارًا)، ولا يدفع شيئًا إن فشل أيّ اختبار. إن نجحت الاختبارات، يُنفَّذ `git add -A && git commit && git push`، وGitHub Pages يحدّث الرابط الحيّ خلال دقيقة أو دقيقتين.

للتجربة محلّيًّا بلا نشر:

```bash
npm run serve   # يفتح خادمًا على http://127.0.0.1:8745
npm test        # اختبارات القبول وحدها
```

- لا توجد بيانات طلاب في هذا المشروع إطلاقًا (خلافًا لموقع «الجريدة الشخصية»)، فلا داعٍ لأيّ تشفير.
- الموقع لا يولّد نصًّا للطالب بتصميم متعمَّد — فحص `npm test` لا يغطّي هذه القاعدة لأنّها تصميميّة لا برمجية، فتحقّق يدويًّا عند أيّ تعديل مستقبليّ أنّك لم تُضِف زرّ «اكتب لي».
